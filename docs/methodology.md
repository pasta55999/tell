# Analysis methodology

All findings are produced by deterministic rules in `tell/analysis/rules/`. Each rule has a
stable ID and version (`tell/analysis/conventions.py`); thresholds are listed there and quoted
in every finding's "How the calculation works" text. Nothing is generated by a language model.

## Definitions

| Term | Definition |
|---|---|
| GMS | Sum of quantity x unit list price on completed orders, before discounts |
| Gross sales | GMS - discounts. Excludes shipping charged and VAT |
| Refunds | Cash refunded, assigned to the **posting month** |
| Net sales | Gross sales of orders placed in the month - refunds posted in the month. Compared with seller-reported revenue |
| COGS | Quantity x unit cost recorded on the order line (fallback: product standard cost). No freight/duty/fulfilment unless embedded |
| Gross profit / margin | Gross sales - COGS; margin = GP / gross sales |
| Contribution proxy | Gross profit - advertising. **Not EBITDA**: no payroll, fulfilment, fees, software, rent |
| ROAS | Platform-attributed revenue / spend, only for channels that report attribution |
| Return rate | Refunded units / units sold for the same SKU and order period (minimum 30 units) |
| Discount rate | Discounts / GMS |

## Rules

| Rule | Module | Logic | Classification |
|---|---|---|---|
| REV-001 | revenue | Monthly `reported_revenue - net_sales`; flag at >= 2% (medium), >= 5% (high), >= 10% (high/critical). Variance attribution tests sums of refunds, cancelled value, shipping and discounts within a 10% residual | discrepancy |
| DSC-001 | revenue | Discount rate >= 12% **and** robust z (median/MAD of other months) >= 3 | suspected risk |
| MAR-001 | profitability | Last-6-month margin >= 3pp below first-6-month margin while gross sales grew; decomposes into unit cost vs selling price change and lists SKU cost drift | suspected risk |
| REF-001 | refunds | SKU return rate >= max(10%, 2 x portfolio) with >= 30 units sold; reason codes summarised | suspected risk |
| REF-002 | refunds | Posting month with >= 8 refunds of lag > 45 days that are >= 25% of the month's refund value | discrepancy |
| REF-003 | refunds | Cohort refund rate (refunds by original order month / gross sales) >= 2 x median of other months, >= 8 refunds | suspected risk |
| ADV-002 | advertising | `reported_ad_spend - sum(channel spend)`; flag at >= 10% (medium), >= 25% (high) | discrepancy |
| ADV-001 | advertising | Ad spend / gross sales with robust z >= 3 and >= 5pp deviation | observation |
| CON-001 | concentration | Top SKU >= 25% or top-3 >= 50% of gross sales; share trend by month | suspected risk |
| CON-002 | concentration | Top category >= 60% | suspected risk |
| INV-001 | inventory | Roll-forward variance per SKU-month: `recorded - (prev + receipts - sold + restocked)`; flag >= 5 units and >= 3% | discrepancy |
| INV-002 | inventory | Any negative on-hand quantity | discrepancy |
| INV-003 | inventory | Supplier receipt unit cost vs average recorded unit cost in the same month, >= 5% | discrepancy |
| SEA-001 | seasonality | Spike = robust z >= 2.5 **and** >= 35% above trailing-6-month median. Classified *seasonal observation (info)* when volume-driven, AOV within 15%, ad intensity within 30%, margin within 8pp, cohort refund rate normal, and at most one check fails; otherwise *suspected risk (medium)* | observation / suspected risk |
| DQ-001 | data_quality | Months with orders but missing statements / ad spend / inventory; units without cost | observation |

## Classification vocabulary

- **Discrepancy** - two records that should agree do not (e.g. statement vs orders). Quantified exactly.
- **Suspected risk** - a pattern that warrants verification; impact is an estimate with a stated basis.
- **Observation** - informational, not a risk (e.g. a seasonal peak).

Status (`detected` -> `needs investigation` -> `verified` / `dismissed`) is set by the analyst, never by the engine.
A finding never becomes an allegation: wording is "reported figure exceeds supported figure", not "fraud".

## Impact estimates

Each finding states its impact basis. Only *discrepancy* impacts are summed in the executive
summary because they measure the same thing (reported vs supported value). Suspected-risk
impacts (e.g. gross profit exposed to a concentrated SKU) are shown individually.

## Reproducibility

An analysis run stores: brand, timestamps, row counts and a SHA-256 content hash of the source
tables, the rule-version map, engine version, findings with evidence rows, generated questions,
skipped analyses and notes. Re-running on unchanged data produces identical findings
(`tests/test_engine.py::test_repeated_run_is_identical`). `compare_runs` diffs two runs by
`finding_key` (= `rule_id:subject`) into new / resolved / changed / unchanged and reports whether
the data hash and rule versions match; it does not claim the business improved.

## What the engine will not do

- Infer advertising attribution from aggregate sales.
- Impute missing costs, statements or snapshots; affected analyses are skipped and listed.
- Call a partial margin EBITDA or net profit.
- Execute free-form SQL from the copilot; intents map to fixed, parameterised functions.
