# Demo dataset: Saffron & Sage

**Provenance.** Entirely synthetic. Generated deterministically by `tell/data/demo_generator.py`
(seed `20250101`) the first time the application starts, and regenerated byte-for-byte on
"Reset demo data". No public dataset is used; nothing describes a real company.

**Business.** A fictional Dubai-based direct-to-consumer home & lifestyle brand selling candles,
ceramics, textiles, kitchenware and decor. Reporting currency AED. Period January-December 2025.

| Dataset | Records | How it is derived |
|---|---|---|
| Products | 20 SKUs in 5 categories | Static list with list price, base unit cost, demand weight |
| Orders / lines | ~1,960 orders, ~2,900 lines | Monthly volume = 130 x 1.025^(month-1) x seasonal factor; 1-4 lines per order; 4% cancelled |
| Refunds / items | ~200 refunds | Per-line refund probability (4.5%; TEX-003 18%); gamma-distributed lag (median ~10 days) |
| Advertising | 12 months x 4 channels | ~14% of gross sales split Meta 42 / Google 28 / Marketplace 18 / TikTok 12; only Marketplace Ads reports attributed revenue |
| Supplier receipts | ~130 goods-received notes | Triggered when stock cover falls below ~1.5 months of demand; priced from the cost schedule |
| Inventory snapshots | 20 SKUs x 13 month-ends | Opening stock + receipts - units sold + restocked returns, then planted distortions |
| Seller statements | 12 monthly P&Ls | Revenue = net sales (+/-0.25% noise); COGS and advertising from records; planted distortions |

## Reconciliation rules the data obeys

```
order.gross_amount   = sum(qty x unit_price)                      (GMS)
order.discount_amount= sum(line_discount)
order.net_amount     = gross_amount - discount_amount             (gross sales; excludes shipping and VAT)
refund.amount        = sum(refund_items.amount)
net sales (month)    = gross sales of completed orders placed in month - refunds POSTED in month
COGS                 = sum(qty x order_items.unit_cost)
expected stock (m)   = recorded stock (m-1) + receipts (m) - units sold (m) + restocked returns (m)
```

## Limitations

- Customer behaviour is i.i.d. per order; there is no repeat-purchase structure, so cohort/LTV analysis is not meaningful.
- Shipping income, VAT, payment fees and fulfilment cost are not modelled; the contribution proxy therefore stops at gross profit less advertising.
- Only one channel reports attributed revenue, by design, to show how ROAS is withheld when attribution is absent.
- Seasonality is a single-year pattern; year-over-year comparisons require a second year of history.
- Public datasets (e.g. Kaggle e-commerce exports) were considered but not bundled: they would require authentication or redistribution licences, and none contains seller-reported statements, inventory and supplier costs needed for reconciliation. The CSV import adapters accept such exports if you have them.
